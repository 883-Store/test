LUOPANICH B / iOS - ต้นแบบกดใช้งาน รอบแรก
วันที่ 2 ตุลาคม 2026

เปิดดู
- preview.html: ดูต้นแบบในกรอบโทรศัพท์, iPad แนวตั้ง/แนวนอน และ PC กดเปลี่ยนขนาดที่แถบด้านบน
- index.html: เปิดต้นแบบเต็มหน้าต่าง ให้ปรับ layout ตามพื้นที่หน้าต่าง
- ใช้ไฟล์ในโฟลเดอร์นี้ร่วมกัน ไม่จำเป็นต้องติดตั้งแพ็กเกจหรือเปิด dev server
- ลิงก์ไฟล์บนคอมพิวเตอร์ไม่ใช่ลิงก์เว็บสาธารณะสำหรับเปิดข้ามเครื่องหรือโทรศัพท์
- ยังไม่ต้องอัปโหลดไฟล์ชุดนี้ทับ GitHub หรือ Apps Script ของร้าน

ขอบเขตความปลอดภัย
- ไม่มีการเชื่อมต่อ API ร้าน, Google Sheets, Apps Script หรือบัญชีร้าน
- ไม่มีรหัสผ่าน/โทเคน/ไฟล์ตั้งค่า Production อยู่ในชุดนี้
- CSP ของ index.html ปิดการเชื่อมต่อเครือข่ายด้วย connect-src 'none'
- การบันทึกและการปรับสต๊อกเปลี่ยนเฉพาะข้อมูลจำลองในหน่วยความจำ
- โหลดหน้าใหม่/ปิดหน้าแล้วเปิดใหม่จะเริ่มข้อมูลใหม่ ร่างไม่ถูกเก็บถาวร
- รูปสินค้า 6 รูปมาจาก URL รูปสาธารณะที่เคยใช้ในการทดสอบ อ่านมาเก็บในชุดไฟล์นี้
- ชื่อสินค้า ราคา สต๊อก ออเดอร์ ลูกค้า และเหตุการณ์เป็นชุดตัวอย่าง ไม่ใช่ยอดปัจจุบันของร้าน

งานที่กดได้
1. ภาพรวม: สลับช่วงวันที่ เปิดรายละเอียดออเดอร์ ไปยังรายการรออนุมัติหรือสินค้าใกล้หมด
2. สินค้า: ค้นหา SKU/ชื่อ กรองหมวดและสต๊อก เรียงรายการ เปิดรายละเอียด
3. ปรับสต๊อกจำลอง: รับเข้า ตัดออก หรือตั้งยอดใหม่ ตรวจยอดติดลบและเหตุผลก่อนบันทึก
4. ไทม์ไลน์: ค้นหา กรองวัน/ประเภท ขยายรายละเอียด และเห็นรายการปรับสต๊อกจำลองที่เพิ่งบันทึก
5. ออเดอร์: ค้นหา กรองสถานะ เปิดดูรายการ และเริ่มเอกสารจากออเดอร์ที่อนุมัติแล้ว
6. เอกสาร: เลือก PO -> ตรวจรายการ -> ตัวอย่าง; รวม PO ของลูกค้าตัวอย่างรายเดียวกันเท่านั้น
7. เลือก PO แล้วค้นหารายการอื่น: รายการที่เลือกก่อนยังอยู่ ไม่หายไปตามผลค้นหา
8. ใบวางบิล: เลือกสินค้า ปรับจำนวนในขอบเขต PO เพิ่มหมายเหตุ บันทึกร่างจำลองและเปิดร่างเดิม
9. ป้องกันร่างซ้ำจาก PO ชุดเดียวกันภายในรอบใช้งานต้นแบบ
10. ใบส่งของ: ระบุจำนวนส่งและดูคงเหลือจาก PO ไม่มีคอลัมน์ราคา
11. ตัวอย่างกระดาษและคำสั่งพิมพ์ผ่านเบราว์เซอร์ มีคำว่าข้อมูลจำลองบนเอกสาร
12. เมนู: เริ่มข้อมูลจำลองใหม่หลังยืนยัน

ลองเส้นทางหลัก
- เอกสาร -> ใบวางบิล -> PO-DEMO-01 -> ใช้ PO ที่เลือก -> ตรวจจำนวน -> ดูตัวอย่าง
- สินค้า -> BY981 -> ปรับสต๊อกจำลอง -> รับเข้า 5 พร้อมเหตุผล -> ดูไทม์ไลน์
- ใน preview.html เปลี่ยนจากโทรศัพท์เป็น iPad/PC โดยไม่โหลดแอปใหม่ ข้อมูลระหว่างลองยังอยู่

การออกแบบ responsive
- มือถือ: รายการแนวตั้ง เมนูหลักล่าง; ระหว่างทำเอกสารเปลี่ยนเป็นปุ่มของงานนั้น
- iPad แนวตั้ง: เมนูด้านข้างแบบย่อและแท็บรายการ/ตัวอย่างเอกสาร
- iPad แนวนอนที่กว้างเพียงพอ: แสดงรายการคู่กับตัวอย่างกระดาษ
- PC: เมนูด้านซ้ายเต็ม และพื้นที่สองส่วนสำหรับงานเอกสาร
- รูปแบบแปรตามความกว้าง ไม่ล็อกตามยี่ห้อหรือรุ่นเครื่อง
- มีการตั้งพื้นที่ safe area, reduced motion และ focus ring ในโค้ด

ผลตรวจ 50/50
- การทดสอบ logic และ DOM จำลองผ่าน 50 ข้อ ดู verification.json
- รวมยอด, จำกัดจำนวน, ข้ามลูกค้า, PO ไม่อนุมัติ, ค้นหา/กรอง, บันทึกร่างซ้ำ, แสดงผลหมายเหตุอย่างปลอดภัย และผลการปรับสต๊อกจำลอง
- ตรวจ parse JavaScript แล้ว และตรวจไฟล์รูป/ฟอนต์/ไอคอนในเครื่อง
- DOM จำลองไม่ใช่ Chrome หรือ Safari จริง ไม่ได้ยืนยัน layout, contrast, touch target หรือการพิมพ์จริง

สิ่งที่ยังไม่ได้ยืนยัน
- เครื่องมือเบราว์เซอร์ปฏิเสธการเปิด file:// ตามนโยบาย จึงไม่มีผล screenshot / responsive browser QA รอบนี้
- ยังไม่ได้ตรวจบนโทรศัพท์, iPad, PC จริง, แป้นพิมพ์มือถือ, การหมุนจอ หรือการแสดง print dialog
- ต้นแบบนี้ยังไม่พร้อมใช้แทนเว็บร้าน ต้องตรวจภาพ/การใช้งานจริงและเทียบกติกาธุรกิจก่อนนำ UI ไปเชื่อมระบบเดิม
- ไม่ครอบคลุมทุกฟีเจอร์ร้าน: ยังไม่มีการล็อกอินจริง, อนุมัติจริง, เพิ่มสินค้า, จัดการผู้ใช้, นำเข้า Excel และส่งออกเป็น PNG
- ใบเอกสารในต้นแบบไม่ใช่แม่แบบ Production และจะไม่ถูกนำไปแทนแม่แบบเดิมโดยอัตโนมัติ
- ไม่จำลองระบบ session/cache/recovery เต็มชุด การนำ UI ไปใช้จริงต้องรักษาส่วนที่ทดสอบแล้วไว้
